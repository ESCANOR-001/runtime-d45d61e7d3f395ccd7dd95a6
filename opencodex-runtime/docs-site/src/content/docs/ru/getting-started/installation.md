:::note
По умолчанию Remodex не изменяет config.toml, каталог моделей и историю чатов Codex. Подключение телефона, запуск и обновление не дают такого разрешения. Описанные ниже синхронизация, изменение и восстановление файлов Codex выполняются только после явного разрешения командой rmx sync --allow-config-change. Команда rmx sync --revoke-config-access отзывает разрешение, не изменяя существующие файлы.

[Codex configuration permission](/reference/cli/lifecycle/#codex-configuration-permission)
:::


Remodex устанавливает основную команду `rmx`. Псевдонимы `remodex`, `ocx` и `opencodex` сохранены
для совместимости; все четыре запускают один небольшой локальный HTTP-сервер (построенный на Bun). Запросы к моделям идут к провайдеру,
выбранному маршрутизацией; опциональные сайдкары для vision и веб-поиска также могут использовать
ваш вход в ChatGPT, когда они нужны маршрутизируемой модели.

## Предварительные требования

| Требование | Зачем |
| --- | --- |
| **[Node](https://nodejs.org) ≥ 20.9** | `rmx` работает на рантайме Bun, но рантайм автоматически поставляется в комплекте при `npm install` — устанавливать Bun самостоятельно **не нужно**. |
| **[OpenAI Codex](https://openai.com/codex)** (CLI, App или SDK) | Клиент, перед которым работает Remodex. Remodex записывает данные в `$CODEX_HOME/config.toml` (по умолчанию `~/.codex/config.toml`). |
| Аккаунт провайдера или API-ключ | Anthropic, xAI, Kimi, Ollama Cloud, OpenRouter, OpenAI-совместимая конечная точка или ваш вход в ChatGPT. |

## Установка

```bash
npm install -g @remodex/rmx
```

:::note[npm заблокировал postinstall-скрипт bun?]
Свежие версии npm могут блокировать postinstall-скрипт bun (`npm warn
install-scripts ... blocked because they are not covered by allowScripts`),
из-за чего встроенный рантайм Bun остаётся неподготовленным. Переустановите
пакет, разрешив скрипт bun, — и обязательно указывайте имя пакета: в
сокращённой подсказке npm его нет, и без него вместо пакета переустановится
текущий каталог:

```bash
npm install -g --allow-scripts=bun @remodex/rmx

# если изначально устанавливали через sudo, продолжайте использовать sudo:
sudo npm install -g --allow-scripts=bun @remodex/rmx
```
:::

Убедитесь, что основная команда доступна в `PATH`:

```bash
rmx --version
```

`remodex`, `ocx` и `opencodex` остаются эквивалентными псевдонимами для совместимости.

После установки обычная настройка выполняется одной командой:

```bash
rmx onboard
```

`rmx onboard` выполняет три этапа: **подготовка компьютера → запуск фоновой службы → подготовка QR-кода**. Во время ожидания выводится ход работы. Страница открывается, как только доступна панель; QR-код появляется после готовности подключения по общей сети Wi-Fi или проверенного удалённого соединения. Отсканируйте код в доверенной общей сети Wi-Fi и дождитесь подтверждения, что новый телефон в сети.

Провайдеры, выбор интеграций и собственные домены сохраняются. Изменение конфигурации Codex, восстановление обновлений и установка значка Windows в трее не блокируют сопряжение. Необязательные действия находятся в **Android Remote → Расширенные настройки**. При первой установке фоновой задачи Windows может запросить права администратора. QR-код действует пять минут; затем можно создать новый.

### Каналы релизов

Стабильный канал `latest` уже включает поддержку каталога GPT-5.6 Sol/Terra/Luna для маршрутов
ChatGPT, OpenAI по API-ключу, OpenRouter и экспериментального Cursor. Доступ у вышестоящего
провайдера по-прежнему зависит от аккаунта; сами по себе записи каталога доступ не дают.
Используйте канал preview только для тестирования ещё не выпущенных сборок Remodex:

```bash
npm install -g @remodex/rmx@preview
rmx update --tag preview
```

## Запуск из исходного кода

Чтобы работать над самим Remodex:

```bash
git clone https://github.com/lidge-jun/opencodex.git
cd opencodex
bun install
bun run dev:proxy   # запускает API прокси в режиме разработки (src/cli/index.ts start)
bun run dev:gui     # запускает dev-сервер панели управления (в другом терминале)
```

`bun run dev` остаётся псевдонимом для `bun run dev:proxy`. API прокси предоставляет `/healthz`,
`/v1/responses` и `/api/*`; `GET /` отдаёт упакованную панель управления только после того, как
`bun run build:gui` создаст `gui/dist`. Пока вы работаете над панелью управления, запускайте
фронтенд отдельно командой `bun run dev:gui`.

## Что создаётся

Состояние Remodex хранится в `$OPENCODEX_HOME` (по умолчанию `~/.remodex`). Файлы интеграции
с Codex находятся в `$CODEX_HOME` (по умолчанию `~/.codex`).

| Путь | Назначение |
| --- | --- |
| `$OPENCODEX_HOME/config.json` | Ваши провайдеры, провайдер по умолчанию, порт и параметры. |
| `$OPENCODEX_HOME/ocx.pid` | PID запущенного прокси (защита от повторного запуска). |
| `$OPENCODEX_HOME/runtime-port.json` | Текущие PID, имя хоста и порт, включая автоматически выбранный запасной порт. |
| `$OPENCODEX_HOME/auth.json` | Сохранённые учётные данные OAuth (после `rmx login`). |
| `$OPENCODEX_HOME/catalog-backup*.json` | Резервные копии каталога моделей Codex, создаваемые перед тем, как Remodex его изменит. |
| `$CODEX_HOME/config.toml` | На loopback-адресе Remodex добавляет корневой `openai_base_url`, отмеченный собственным маркером; при привязке не к loopback используются `model_provider = "opencodex"` и `[model_providers.opencodex]`, чтобы Codex мог отправлять заголовок API-аутентификации. |
| `$CODEX_HOME/opencodex.config.toml` | Резервный/справочный профиль, записываемый рядом с основной конфигурацией Codex. |
| `$CODEX_HOME/opencodex-catalog.json` | Синхронизированный каталог нативных и маршрутизируемых моделей, используемый Codex. |

:::note
Remodex никогда не удаляет вашу конфигурацию Codex. Каждое внедрение обратимо — `rmx stop`,
`rmx restore` или `rmx eject` убирают ровно те строки, которые добавил Remodex, и восстанавливают
нативный Codex.
:::
